problem, documenting the reasoning and trade-offs behind each solution.

---

## Why this repo

Anyone can paste a solution. The notes here capture the part that actually matters:
how I break a problem down, what I tried first, why it didn't hold up, and what the
final approach costs in time and space.

## Structure

```
hackerrank-journey/
├── README.md
└── software-engineer-prep-kit/
    └── Count Elements Greater Than Previous Average/
        ├── notes.md
        ├── screenshot.png
        └── testresults.png
```

## Method

1. Restate the problem in my own words.
2. Write the brute-force approach first — confirm I understand the mechanics.
3. Find the bottleneck and work toward something better.
4. State the time and space complexity of what I settled on.
5. Test edge cases: empty input, single element, duplicates, extremes.
6. Write the notes before starting the next problem.
